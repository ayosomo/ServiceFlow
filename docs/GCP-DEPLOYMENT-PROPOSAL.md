## Purpose and choice

Demonstrate BA-004/006: an authenticated manager reads independently checked operational KPIs and drills into the records behind them. Use one temporary London (`europe-west2`) Cloud Run service, one regional Firestore Standard Native database and one private Docker repository. Keep the three labs independent.

Create a new project with an available `serviceflow-insights-` prefixed ID, record its exact ID privately before changes and link only the already reviewed trial billing account. A dedicated project keeps runtime permissions and teardown separate from the existing default project, which has unrelated APIs enabled and has not been completely inventoried. No existing project is renamed, repurposed or deleted. The exact new ID depends on global availability; a failed name check permits choosing another ID with this prefix, not modifying an existing project.

## Cost model and protections

The [reproducible GBP scenario](evidence/gcp-retail-cost-scenario.json) uses official catalogue prices retrieved on 24 October, effective 07:00 UTC that day. It deliberately applies paid marginal rates before free allowances or promotional credit:

| Assumed usage                                                                          | Approximate gross GBP |
| -------------------------------------------------------------------------------------- | --------------------: |
| 1 vCPU + 256 MiB active for an entire hour                                             |               0.09357 |
| 100 HTTP requests and 100 MiB internet response data to Europe                         |               0.00776 |
| 30 Firestore reads, one create/delete, 5 MiB readback egress, 10 MiB storage for a day |               0.00048 |
| 1 GiB registry image storage for an hour                                               |               0.00010 |
| 10 MiB log ingestion                                                                   |               0.00368 |
| Total                                                                                  |           **0.10559** |

This is a roughly **£0.11 rounded-up planning scenario**, not measured spend, a worst-case guarantee or permission to incur cash charges. Startup/shutdown, retries, index overhead and delayed cleanup can differ. The catalogue's storage conversion for these SKUs is 31 days. Firestore storage is measured daily, so the model reserves a full day for 10 MiB despite the one-hour operating target; registry remains one hour. Direct operator Firestore readback reserves an additional 5 MiB of Europe internet egress. A 100 MiB Europe egress allowance is modelling headroom, not a traffic generator. Reprice a different destination. No free allowance is assumed unused elsewhere.

Cloud Run's grant is shared across the billing account and based on Tier 1 spending equivalents; London is Tier 2. Firestore allows one eligible free database per project; registry free storage is aggregated across the billing account. Keep services colocated, build locally, push inbound only, and do not pull the uploaded image back to the laptop. Same-region service traffic avoids cross-region costs. No VPC connector, NAT gateway, load balancer, managed SQL, marketplace purchase, AI feature or always-on compute is included.

Google documents no usage billing during an active Free Trial; expiry/exhaustion stops resources unless the owner upgrades. This is the financial basis for expected £0 new cash spend. Trial credit consumption is still usage and must be reported honestly. If Paid account appears, credit is unavailable/expired, service access requires upgrading, or coverage is unclear: **stop and tear down the newly created lab resources**. Do not click Upgrade/Activate or change payment arrangements.

Ordinary alerts-only budgets are not automatic shutoffs. Google now also documents Cloud Run spend-cap budgets, but they operate on delayed estimated gross cost and do not cover Firestore/registry storage; no universal or instantaneous cap is claimed. The current account has no verified enforced cap. This proposal does **not** create budgets, subscriptions or email alerts. It relies on retaining the Free Trial plus bounded traffic, scale and teardown. A budget/cap setup would be a separately reviewed change.
