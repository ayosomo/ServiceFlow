# Threat model and operational limits

Trust boundaries: caller → gateway → Lambda → DynamoDB; CSV blob → Function → results; caller → Cloud Run → Firestore. Input files and request bodies are untrusted data.

| Threat                            | Implemented control                                                                                  | Remaining verification                                                                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Anonymous/role escalation         | IAM route defaults; server principal allowlists; GCP signature/audience/email checks                 | AWS and GCP historical live negative checks passed; new AWS controls local-only                                                                |
| Own decision or absent provenance | Exact submitting-principal exclusion, one matching server submission audit, checked before replay    | Unit faults and DynamoDB Local denial; different sessions/accounts may belong to one human; cloud/human separation unverified                  |
| Lost updates/double decisions     | Conditional transactional version + request/event/receipt                                            | AWS persistence/replay/stale checks passed; concurrency race tested locally                                                                    |
| Oversized/malformed input         | 16 KiB API, 1 MiB CSV, 200 rows, strict schemas                                                      | Host trigger memory limits under load                                                                                                          |
| Duplicate source delivery         | SHA-256, ETags, immutable findings, create-only summary                                              | Local Blob integration/host passed; Azure cloud remains unverified                                                                             |
| Uncertain transaction response    | Actor/path/key-scoped receipt and atomic request/event/receipt write                                 | Local real commit followed by injected lost acknowledgement passed; a 503 does not prove no mutation; real provider outage/recovery unverified |
| Partial report write              | Summary committed last; full findings embedded; replay repairs convenience file                      | Orphan immutable blobs need manual cleanup                                                                                                     |
| Source races                      | Conditional ETag reads and recheck before commit                                                     | Upload discipline: batch IDs immutable after upload; two blobs are not a database transaction                                                  |
| Sensitive logs                    | Bounded operation/status/outcome/duration/correlation only; no request/token/provider-detail logging | AWS and bounded GCP live logs inspected; Azure cloud logs unverified; no complete log inventory claimed                                        |
| Credentials in Git                | Ignore local settings/.env/keys; placeholder configuration                                           | Scan checked-in text before publication                                                                                                        |
| Cost/abuse                        | No cloud action by default; AWS throttle, concurrency 1; GCP max 1/min 0 runbook                     | Quotas and alerts are not universal hard spending caps                                                                                         |

Local random tokens are development authentication only. Cloud modes cannot use local tokens in Cloud Run. The AWS template's explicit data policy is restricted to its table; standard Lambda execution policy handles logging. The owner's new AWS project experience has managed defaults that can grant code broader project access, so effective least privilege is not yet verified. Demo owner access is broader than a production caller role; one operator exercising all application roles does not establish separation of duties. Only IAM-authorised Azure uploaders should write incoming blobs; no anonymous HTTP ingestion route exists.

Timeouts, bounded SDK retries and deterministic idempotent work reduce duplicate effects. Audit and idempotency records have no TTL in this small demo: replay remains stable until explicit teardown. Production would need a defined retention and retry window. No automated resolution workflow or business outcome savings is claimed.

Current AWS decisions require submission provenance even for an existing receipt. Future audit archival/history beyond the bounded read must preserve that provenance. Missing legacy audit fails closed; no silent actor backfill is implemented. [Production backlog and incident/retry playbook](AWS-PRODUCTION-READINESS.md). Authenticated `/healthz` is process liveness only, not a dependency/readiness or availability guarantee.

Generated request IDs use UUID v4; IDs are references, not secrets or authorisation. Forced collisions still fail without overwrite. Local package checks reject changed bytes against an independently retained expected digest; changing both the package and trusted digest defeats that boundary. The cooperative journal is not a tamper-proof audit or production access control. No untrusted package execution is authorised. Rule-version mismatch prevents an old summary silently appearing current. [Limits and migration risks](AWS-LOCAL-RELEASE-AND-IDENTIFIERS.md).
